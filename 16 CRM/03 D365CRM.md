```text
                 User Action

                     ▼

           Azure Service Bus Topic
        ┌──────────┼──────────┐
        ▼          ▼          ▼

        ▼          ▼          ▼

Because one event needs multiple subscribers.

```

↓

↓

↓

↓

Many subscribers

↓

Better scalability.

# 2. Implement Idempotent APIs

## Interview Question

### Answer

Calling API multiple times should produce same result.

Example

```

Create Invoice
```

Suppose

Network timeout.

Client retries.

Without Idempotency

```
Invoice 1001

```

Wrong.

---

## Correct Design

Client sends

```
Idempotency-Key

ABC123
```

Server

```
Check Table

↓

Already Exists?

↓

Return Existing Response
```

No duplicate.

---

```

↓

↓

```

Best for Web Apps.

---

```

↓

↓

Nobody else edits
```

Used in Banking.

---

| Optimistic       | Pessimistic       |
| ---------------- | ----------------- |

# 9. Design Retry Strategy with Circuit Breaker

Suppose

ERP Down.

Without Circuit Breaker

```
1000 Requests

↓

ERP

↓

Fail
```

Server crashes.

---

Circuit Breaker

```
Fail

↓

Open Circuit

↓

Stop Calls

↓

Wait 30 sec

↓

Half Open

↓

Success?

↓

Close Circuit
```

---

## Polly Example

```csharp
Policy
.Handle<HttpRequestException>()
.WaitAndRetryAsync(3,
retry => TimeSpan.FromSeconds(Math.Pow(2,retry)));
```

---

Circuit Breaker

```csharp
Policy
.Handle<HttpRequestException>()
.CircuitBreakerAsync(
5,
TimeSpan.FromSeconds(30));
```

# Interview Tips (Architect-Level)

When answering these questions, follow this structure:

1. **Clarify the requirement** (functional and non-functional needs).
2. **Draw the architecture** and explain each component.
3. **Discuss scalability** (queues, partitions, autoscaling).
4. **Discuss reliability** (retries, dead-letter queues, idempotency, monitoring).
5. **Discuss security** (Managed Identity, OAuth, Key Vault, RBAC).
6. **Discuss trade-offs** (why you chose one Azure service over another).
7. **Mention monitoring and observability** (Application Insights, Azure Monitor, Log Analytics).
8. **Highlight failure handling** (timeouts, circuit breakers, compensation).

This structured approach is what distinguishes a senior developer or architect from someone who only knows the implementation details.
